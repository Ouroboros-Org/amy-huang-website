# Glossary

| Term | Meaning |
|---|---|
| Acceptance | Observable results that show an outcome is reached. An Issue closes when they are verified. |
| Delivery | The result reached its delivery path, with evidence. Merging is not delivery; see [Acceptance and delivery](Acceptance-and-delivery.md). |
| Disposition | The recorded decision about an Issue or a review finding: placed, linked, postponed, closed, kept open, fixed or accepted, each with its reason. |
| Exact head | The specific commit a review covers. A merge uses that commit, and a later push needs a new review. |
| Grooming | The routine that keeps the handbook relevant and connected. See [Groom the Wiki](Wiki-maintenance.md#groom-the-wiki). |
| Handed off | The Issue or pull request owns execution. It says nothing about delivery. |
| Horizon | A milestone that groups work by when it should happen: soon, after, later or some time. See [Choose a horizon](Project-planning.md#choose-a-horizon). |
| Kept open | An Issue left open on purpose, with the reason in a comment. |
| Outcome | One concrete problem to solve or result to reach, owned by an Issue or a small pull request. |
| Ready | Bounded acceptance, known checks and satisfied dependencies. Ready does not authorize implementation outside the selected horizon. |
| Routine | A recurring pass that keeps records healthy, run separately from ordinary work at a pace set by throughput. |
| Triage-refinement | The routine that sorts, researches, connects and prepares Issues. See [Triage and refinement](Triage-and-refinement.md). |
